# Changelog

## 1.1.0

- Validated withTimestamps option routes HTTP TTS/dialogue through /with-timestamps and music through /v1/music/detailed; decoded audio retains camelCase alignment, normalizedAlignment, voiceSegments and lyric wordTimestamps metadata plus exact raw JSON. eleven_v4 automatically uses single-voice Text to Dialogue; explicit inputs retain multi-voice behavior. Generic wav maps to wav_44100. Streaming speech warns for unsupported withTimestamps while preserving existing WS alignments. Binary-safe multipart music decoding accepts reversed metadata/audio order, Unicode, empty audio and boundary-lookalike bytes; rejects missing/duplicate parts, invalid metadata and incomplete framing. Object, validation-array, string detail and legacy error envelopes preserve typed provider message/code separately from raw responseBody, response headers and status, including transcription and native extended audio clients. Additive native async apiKeyProvider resolves at each HTTP send/stream and WS connect, preserves case-insensitive caller overrides, propagates supplier failures before transport and excludes auth from reported WS init metadata. Reviewed upstream: @ai-sdk/elevenlabs 3.0.71 to 3.0.76. Validation passed: node Scripts/test-packages.mjs (all 52 owning package suites and the compatibility facade); node Scripts/sdk.mjs generate --check; node --test Scripts/tests/*.test.cjs (27 passed); docs-site check and build (100 pages). Live provider calls were not run.
  Compatibility: Minor release for additive native API; existing static settings and call sites remain compatible. Updated direct dependency minimums are recorded in the manifest. Existing documented JS/framework and native product gaps remain; version-delta review does not imply full parity or live-service testing. Explicit custom authentication skips an unused credential supplier, a deliberate native callback-order adaptation.
